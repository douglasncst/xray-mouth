## Architecture and implemented functionality

The project is a local Python CLI, not a web application or diagnostic system.
`ImageSource` / `FolderImageSource` discover files; `Protocol`, `RadiographSlot`,
`Radiograph`, `Exam`, and `ExportResult` model the data. Imaging maps filename
prefixes and creates non-destructive grayscale render copies. Layout uses
normalized rectangles for the 14-position series. Workflow coordinates
validation and preview PNG / 600-DPI canvas / ReportLab PDF / text report output.
The existing architecture, position geometry and interfaces were retained.

There is no automatic image-content exam classification, anatomical recognition,
DICOM import, hardware acquisition, encryption, or clinical validation. Slots
are identified only by ASCII filename prefixes. Alternative protocols require
new renderer geometry; the workflow now rejects unsupported geometry early.

## Findings and corrections

- Demo could reuse existing images or mix synthetic and patient data. It now
  requires an empty/new folder and creates files exclusively without overwrite.
- API contrast accepted zero/negative/non-finite values; CLI accepted NaN and
  infinity. Both now validate finite positive contrast before filesystem work.
- Names could inject lines/control characters into reports, overflow paths,
  or overrun the center panel. Names are bounded and printable, directory slugs
  are bounded by UTF-8 bytes, and display text fits its region while the report
  retains full text.
- Pillow structure verification alone missed truncated BMP pixel data. Full
  decoding now precedes export. Unsupported content disguised as supported
  extensions, multiple frames/pages, unsafe high-bit-depth conversion, and
  decompression-bomb conditions are rejected explicitly. Symlinked image files
  are rejected rather than silently importing external files.
- Duplicates were checked only by slot. SHA-256 now rejects byte-identical files
  assigned to different slots. Re-encoded/visually similar images remain outside
  this check. Error filenames and report filenames escape control characters.
- `thumbnail()` never enlarged small images, so the detail canvas could contain
  tiny radiographs. Aspect-preserving fitting now scales both directions.
  Transparent pixels are composited onto black before grayscale conversion.
- Font fallback used unsupported Pillow 10.0 arguments and attributes. Fallback
  and font annotations now support that declared minimum. Long labels are
  bounded to their slots; excess metadata remains available in the report.
- Filesystem errors could escape the CLI as tracebacks and leave partial exports.
  Expected filesystem errors now become application errors, newly created partial
  result directories are cleaned on ordinary failure, and existing exports are
  preserved. Directory creation retries collisions and handles broken symlinks;
  an output root that is a file returns an error without looping.
- New result directories are owner-only on POSIX. Source EXIF is not propagated
  to generated canvases. The detail PNG now contains 600-DPI metadata. Failure
  to open a saved PDF on Windows produces a warning rather than losing success.
- CI now checks formatting in addition to lint/tests and has read-only repository
  permissions. README, contributing guidance, architecture and ignore rules were
  updated only for the corrected behavior and audit workflow.

## Remaining risks and next steps

- Native Windows launcher, ACLs, automatic PDF opening and physical hardware
  remain unvalidated. No real clinical data was supplied; end-to-end runs used
  synthetic fixtures with real Pillow/ReportLab operations.
- Forced termination, disk failure during cleanup, or concurrent source edits
  can leave partial or inconsistent exports. The workflow is not crash-atomic.
- Patient identifiers appear in paths, reports, rendered pixels and CLI output.
  Files are unencrypted; existing output-root permissions are untouched.
  Cloud execution is not processing on the user's local workstation. Source
  pixel annotations cannot be removed by metadata stripping.
- High-bit-depth and multipage files must be explicitly converted/exported
  upstream. Automatic windowing or page-to-slot assignment was not invented.
- No content-based anatomical validation or visual-duplicate detection is
  provided; incorrect filename labels can still produce a misleading series.
- Dependencies have lower bounds without a reproducible lock/constraints file.
  Static type checking remains an optional audit command rather than a CI gate.

Recommended next work: validate the workflow on native Windows and approved,
de-identified acquisition samples; agree on high-bit-depth windowing and exam
classification requirements; then implement and test those capabilities behind
explicit interfaces. Review this branch against `feat/initial-xray-mouth-core`
so the audit fixes are separated from the unmerged initial implementation.
